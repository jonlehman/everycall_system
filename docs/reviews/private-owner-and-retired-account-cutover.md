## Fixed-Dave carrier operator transport

The canonical `POST /api/v1/operator/retire-daved-number` is one expiring operation, not a general admin API. It rejects GET, query/body-selected targets and absent/invalid credentials. A separate 256-bit random capability is stored only as a hash under a special `auth_tokens` type; normal invite/password-reset authentication cannot consume it. The responsible operator is existing admin 1. The company owner's chat decision is recorded separately; this is not an impersonated owner session. Capability lifetime is at most 15 minutes and the route permanently refuses effects after its reviewed November 14 UTC sunset.

After deploying the final reviewed source and confirming all three runtimes plus the 810-second retirement, prepare a private authorization bundle with source/target/tenant fingerprint pins, owner decision, independent review, canonical Stripe-closure and carrier-ownership evidence hashes, and actual runtime/retirement evidence. `node scripts/authorize-retired-number-release.mjs /private/bundle.json SHA256` is a dry run. Execution requires `EVERYCALL_AUTHORIZE_DAVED_NUMBER_RELEASE=1` and a new third argument `/private/capability.json`; the CLI stores that secret file with mode 0600 and never prints the capability.

Invoke only through `node scripts/invoke-retired-number-release.mjs /private/capability.json /private/new-request-receipt.json`. It performs one direct canonical HTTPS POST, with the capability solely in Authorization, no redirect and no automatic retry. It makes no Vercel protection or global SSO change. The private local journal records prepared/received/unknown outcomes without the token.

The runtime verifies exact Dave tenant/customer/subscription/number/phone-hash bindings and no active work/shared number. An authenticated GET of the preserved owner's fixed resource provides a positive account/connection control; only Dave's positively matched resource is released. The existing Telnyx one-number deletion-job POST is the sole provider mutation. Token consumption and a resource-keyed submitted audit intent commit before it; database locks are never held across network I/O. A crash or unknown outcome cannot authorize another submission, including with a replacement capability. Later invocations perform canonical GET reconciliation only. A positive, authenticated exact-resource 404 after the owned intent is the completion proof; acceptance alone is not completion. Local phone fields remain intact until guarded hard purge.

The intent/grant/reconciliation records use existing audit storage, preserving 0065 SQL SHA256 `a410dce72f24273789c89d779b31f2914f5fe21e10b64c93b468f1931c41b5ea` and avoiding new financial FK dependencies. An expired capability may be replaced only through a new reviewed grant; any prior resource intent forces the replacement to be reconciliation-only. `scripts/test-retired-number-release.mjs` uses a disposable database and provider doubles, substituting only synthetic phone hashes and operational test expiry; it covers capability isolation, retirement/source binding, authenticated provider-control/phone/connection mismatch and initial-absence refusal, transactional intent failure, concurrent at-most-once submission, accepted-timeout uncertainty, replacement-token fencing, preserved local mapping/owner state and fixed HTTP scope.
